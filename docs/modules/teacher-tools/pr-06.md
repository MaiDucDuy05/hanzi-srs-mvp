## 1. Yêu cầu nghiệp vụ

Giáo viên tạo, sửa, xoá và phân loại câu hỏi theo cấp HSK, bài học và dạng bài. Câu hỏi được tổ chức thành ngân hàng câu hỏi dùng chung (Public — do Admin tạo) và riêng (Private — do Giáo viên tạo).

### 1.1. Luồng tạo câu hỏi

1. Giáo viên vào trang "Ngân hàng câu hỏi" → bấm "Tạo câu hỏi".
2. Chọn loại câu hỏi:
   - **Trắc nghiệm (MCQ)**: Nội dung câu hỏi + 4 đáp án + 1 đáp án đúng.
   - **Điền chỗ trống (Fill-in)**: Câu có chỗ trống + đáp án đúng (hỗ trợ nhiều đáp án chấp nhận được).
   - **Sắp xếp câu (Ordering)**: Câu gốc đúng + hệ thống tự xáo trộn khi ra đề.
   - **Nối từ (Matching)**: Danh sách cặp tương ứng.
3. Nhập metadata:
   - Cấp HSK (1-9).
   - Bài học liên kết (optional).
   - Tag/nhãn tự do (VD: "ngữ pháp", "từ vựng", "lượng từ").
   - Độ khó: Dễ / Trung bình / Khó.
4. Thêm giải thích (optional): Hiển thị cho học sinh sau khi nộp bài.
5. Bấm "Lưu" → Câu hỏi mặc định trạng thái `Private` (chỉ giáo viên tạo thấy).

### 1.2. Phân quyền câu hỏi

| Vai trò | Quyền |
| :--- | :--- |
| Teacher | Tạo câu hỏi Private. CRUD đầy đủ câu của mình. Xem câu Public (read-only). |
| Admin | Tạo câu hỏi Public (dùng chung toàn hệ thống). CRUD mọi câu Public. Có thể ẩn câu Private vi phạm. |

### 1.3. Quy tắc chính

* Câu hỏi đã được dùng trong bài kiểm tra có học sinh nộp → không được xoá, chỉ được ẩn (soft delete).
* Trắc nghiệm phải có ít nhất 2 đáp án và đúng 1 đáp án đúng.
* Điền chỗ trống hỗ trợ nhiều đáp án chấp nhận (VD: "的" hoặc "de").
* Import hàng loạt bằng CSV/Excel (nice-to-have cho v1, không bắt buộc).

## 2. Thiết kế dữ liệu

### 2.1. Bảng `questions`

| Cột | Kiểu | Mô tả |
| :--- | :--- | :--- |
| `id` | UUID, PK | |
| `creator_id` | UUID, FK → users | Người tạo |
| `type` | ENUM(`MCQ`, `FILL_IN`, `ORDERING`, `MATCHING`) | Loại câu hỏi |
| `visibility` | ENUM(`PUBLIC`, `PRIVATE`) | Phạm vi hiển thị |
| `hsk_level` | INT, nullable | Cấp HSK (1-9) |
| `lesson_id` | UUID, FK → lessons, nullable | Bài học liên kết |
| `difficulty` | ENUM(`EASY`, `MEDIUM`, `HARD`) | Độ khó |
| `content` | JSONB | Nội dung câu hỏi (xem cấu trúc bên dưới) |
| `explanation` | TEXT, nullable | Giải thích đáp án |
| `tags` | TEXT[], nullable | Nhãn phân loại |
| `is_active` | BOOLEAN, default true | Soft delete |
| `created_at`, `updated_at` | TIMESTAMP | |

### 2.2. Cấu trúc JSONB `content` theo loại

**MCQ:**
```json
{
  "question_text": "他 ___ 学生。",
  "options": [
    { "id": "a", "text": "是" },
    { "id": "b", "text": "有" },
    { "id": "c", "text": "在" },
    { "id": "d", "text": "去" }
  ],
  "correct_answer": "a"
}
```

**FILL_IN:**
```json
{
  "sentence": "我喜欢吃___。",
  "blank_index": 1,
  "accepted_answers": ["苹果", "píngguǒ"]
}
```

**ORDERING:**
```json
{
  "correct_order": ["我", "喜欢", "吃", "苹果"],
  "display_shuffled": true
}
```

**MATCHING:**
```json
{
  "pairs": [
    { "left": "苹果", "right": "Táo" },
    { "left": "香蕉", "right": "Chuối" }
  ]
}
```

## 3. Triển khai Backend — NestJS

### 3.1. Cấu trúc module

```text
question-bank/
  question-bank.controller.ts
  question-bank.service.ts
  entities/
    question.entity.ts
  dto/
    create-question.dto.ts
    update-question.dto.ts
    query-questions.dto.ts
```

### 3.2. API cần triển khai

| Method | Endpoint | Actor | Chức năng |
| :--- | :--- | :--- | :--- |
| POST | `/api/questions` | Teacher, Admin | Tạo câu hỏi |
| GET | `/api/questions` | Teacher, Admin | Danh sách (filter, pagination) |
| GET | `/api/questions/:id` | Teacher, Admin | Chi tiết câu hỏi |
| PUT | `/api/questions/:id` | Owner | Cập nhật |
| DELETE | `/api/questions/:id` | Owner | Soft delete (nếu chưa dùng trong exam) |

**Query params cho GET `/api/questions`:**
* `type` — Loại câu hỏi.
* `hsk_level` — Cấp HSK.
* `difficulty` — Độ khó.
* `visibility` — PUBLIC / PRIVATE.
* `tags` — Lọc theo nhãn.
* `search` — Tìm kiếm full-text trong nội dung.
* `page`, `limit` — Phân trang.

### 3.3. Validation

* MCQ: Kiểm tra `correct_answer` nằm trong danh sách `options`.
* FILL_IN: `accepted_answers` phải có ít nhất 1 phần tử.
* ORDERING: `correct_order` phải có ít nhất 2 phần tử.
* MATCHING: `pairs` phải có ít nhất 2 cặp.
* `hsk_level` phải trong khoảng 1-9.

## 4. Triển khai Frontend — NextJS

### 4.1. Route và thành phần

| Route/Component | Vai trò |
| :--- | :--- |
| `/teacher/questions` | Danh sách câu hỏi (bảng + filter sidebar) |
| `/teacher/questions/create` | Tạo câu hỏi mới |
| `/teacher/questions/[id]/edit` | Chỉnh sửa câu hỏi |
| `QuestionForm` | Form tạo/sửa (dynamic theo type) |
| `QuestionPreview` | Xem trước câu hỏi như học sinh thấy |
| `FilterPanel` | Bộ lọc HSK, loại, độ khó, tags |

### 4.2. Cách xử lý giao diện

* Khi chọn loại câu hỏi, form thay đổi động (MCQ hiện 4 ô đáp án, ORDERING hiện danh sách kéo thả...).
* Preview bên phải cho giáo viên xem câu hỏi "như học sinh thấy".
* Bảng danh sách có search bar full-text, filter chip và pagination.
* Badge hiển thị số câu hỏi đã dùng trong exam (nếu > 0, disable nút xoá).

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo bảng `questions` và migration.
2. API CRUD + validation cho từng loại câu hỏi.
3. API danh sách với filter + pagination.
4. Frontend: Form tạo câu hỏi MCQ trước (phổ biến nhất).
5. Mở rộng form cho FILL_IN, ORDERING, MATCHING.
6. Frontend: Danh sách + filter + preview.
7. Seed dữ liệu mẫu câu hỏi Public.

## 6. Tiêu chí hoàn thành

PR-06 được nghiệm thu khi:

* Giáo viên tạo được câu hỏi ở cả 4 loại (MCQ, FILL_IN, ORDERING, MATCHING).
* Câu hỏi Private không hiển thị cho giáo viên khác.
* Câu hỏi Public hiển thị cho tất cả (read-only nếu không phải Admin).
* Filter hoạt động đúng theo HSK, loại, độ khó, tags.
* Không xoá được câu hỏi đã dùng trong bài kiểm tra có submission.
* Validation backend đúng theo quy tắc từng loại câu hỏi.
