## 1. Yêu cầu nghiệp vụ

Giáo viên tạo lớp, quản lý danh sách học sinh. Học sinh tham gia lớp bằng mã lớp.

### 1.1. Luồng giáo viên tạo lớp

1. Giáo viên vào trang "Lớp học" → bấm "Tạo lớp mới".
2. Nhập: Tên lớp, Mô tả (optional), Cấp HSK mục tiêu (optional).
3. Bấm "Tạo" → Hệ thống sinh **Class Code** gồm 6 ký tự alphanumeric (VD: `AB3K9X`), duy nhất toàn hệ thống.
4. Giáo viên chia sẻ Class Code cho học sinh (qua Zalo, email, v.v.).

### 1.2. Luồng học sinh tham gia lớp

1. Học sinh vào trang "Tham gia lớp" → nhập Class Code.
2. Hệ thống hiển thị tên lớp + tên giáo viên để xác nhận.
3. Học sinh bấm "Xin tham gia" → trạng thái: `PENDING`.
4. Giáo viên vào tab "Chờ duyệt" → thấy danh sách học sinh chờ.
5. Giáo viên bấm "Duyệt" hoặc "Từ chối":
   - **Duyệt**: Trạng thái → `ACTIVE`, học sinh thấy nội dung lớp.
   - **Từ chối**: Trạng thái → `REJECTED`, học sinh nhận thông báo.

### 1.3. Quản lý thành viên

* Giáo viên xem danh sách học sinh theo trạng thái (Active, Pending).
* Giáo viên có thể **Remove** (xóa) học sinh khỏi lớp bất kỳ lúc nào.
* Học sinh có thể tự **Rời lớp**.
* Giáo viên có thể **Đổi Class Code** (vô hiệu hóa code cũ, sinh code mới).

### 1.4. Quy tắc chính

* Không giới hạn số lớp mỗi giáo viên.
* Giới hạn 50 học sinh/lớp (v1). Cấu hình được từ Admin.
* Class Code case-insensitive (nhập `ab3k9x` cũng match `AB3K9X`).
* Học sinh đã bị Reject không thể xin tham gia lại cùng lớp (cần giáo viên mời trực tiếp hoặc reset).
* Giáo viên chỉ quản lý lớp mình tạo.

## 2. Thiết kế dữ liệu

### 2.1. Bảng `classrooms`

| Cột | Kiểu | Mô tả |
| :--- | :--- | :--- |
| `id` | UUID, PK | |
| `teacher_id` | UUID, FK → users | Giáo viên sở hữu |
| `name` | VARCHAR(100) | Tên lớp |
| `description` | TEXT, nullable | Mô tả |
| `hsk_level` | INT, nullable | Cấp HSK mục tiêu |
| `class_code` | VARCHAR(8), UNIQUE | Mã lớp |
| `max_students` | INT, default 50 | Giới hạn sĩ số |
| `is_active` | BOOLEAN, default true | Trạng thái lớp |
| `created_at`, `updated_at` | TIMESTAMP | |

### 2.2. Bảng `classroom_members`

| Cột | Kiểu | Mô tả |
| :--- | :--- | :--- |
| `id` | UUID, PK | |
| `classroom_id` | UUID, FK → classrooms | |
| `student_id` | UUID, FK → users | |
| `status` | ENUM(`PENDING`, `ACTIVE`, `REJECTED`, `REMOVED`) | Trạng thái |
| `joined_at` | TIMESTAMP, nullable | Ngày được duyệt |
| `created_at` | TIMESTAMP | Ngày xin tham gia |

**Unique constraint:** `(classroom_id, student_id)`.

### 3.2. API cần triển khai

**Giáo viên:**

| Method | Endpoint | Chức năng |
| :--- | :--- | :--- |
| POST | `/api/classrooms` | Tạo lớp (sinh class_code) |
| GET | `/api/classrooms` | Danh sách lớp của mình |
| GET | `/api/classrooms/:id` | Chi tiết lớp |
| PUT | `/api/classrooms/:id` | Cập nhật thông tin lớp |
| DELETE | `/api/classrooms/:id` | Xóa lớp (soft delete) |
| POST | `/api/classrooms/:id/regenerate-code` | Sinh class_code mới |
| GET | `/api/classrooms/:id/members` | Danh sách thành viên (filter theo status) |
| PUT | `/api/classrooms/:id/members/:memberId/approve` | Duyệt học sinh |
| PUT | `/api/classrooms/:id/members/:memberId/reject` | Từ chối |
| DELETE | `/api/classrooms/:id/members/:memberId` | Xóa học sinh khỏi lớp |

**Học sinh:**

| Method | Endpoint | Chức năng |
| :--- | :--- | :--- |
| POST | `/api/classrooms/join` | Xin tham gia bằng class_code |
| GET | `/api/classrooms/my` | Danh sách lớp đã tham gia |
| DELETE | `/api/classrooms/:id/leave` | Rời lớp |

### 3.3. Logic sinh Class Code

* Sinh chuỗi 6 ký tự: `A-Z, 0-9`, loại bỏ ký tự dễ nhầm (`0/O`, `1/I/L`).
* Kiểm tra trùng trong DB trước khi lưu (retry tối đa 5 lần).
* Lưu dạng uppercase, so sánh case-insensitive.

### 3.4. Xử lý lỗi

* Class Code không tồn tại: `CLASS_NOT_FOUND`.
* Lớp đã đầy: `CLASS_FULL`.
* Học sinh đã ở trong lớp: `ALREADY_JOINED`.
* Học sinh đã bị từ chối: `PREVIOUSLY_REJECTED`.
* Không phải chủ lớp: 403 Forbidden.

## 4. Triển khai Frontend — NextJS

### 4.1. Route và thành phần

| Route/Component | Vai trò |
| :--- | :--- |
| `/teacher/classrooms` | Danh sách lớp của giáo viên |
| `/teacher/classrooms/create` | Tạo lớp mới |
| `/teacher/classrooms/[id]` | Chi tiết lớp (tab: Members, Posts, Results) |
| `/student/classrooms` | Danh sách lớp của học sinh |
| `/student/classrooms/join` | Nhập class code để xin tham gia |
| `ClassCodeDisplay` | Hiển thị class code + nút copy |
| `MemberList` | Danh sách thành viên + nút Approve/Reject |
| `PendingBadge` | Badge đỏ hiển thị số học sinh chờ duyệt |

### 4.2. Cách xử lý giao diện

* Trang chi tiết lớp dùng Tab layout: **Thành viên** | **Bài đăng** | **Kết quả**.
* Class Code hiển thị dạng lớn, dễ đọc, có nút Copy to clipboard.
* Danh sách thành viên Pending hiển thị với badge đỏ để giáo viên chú ý.
* Trên mobile, danh sách thành viên hiển thị dạng card (swipe để Approve/Reject).

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo bảng `classrooms` + `classroom_members`.
2. API tạo lớp + sinh class code.
3. API join lớp (học sinh).
4. API approve/reject (giáo viên).
5. API danh sách thành viên.
6. Frontend Teacher: Tạo lớp + quản lý thành viên.
7. Frontend Student: Join lớp + danh sách lớp.

## 6. Tiêu chí hoàn thành

PR-20 được nghiệm thu khi:

* Giáo viên tạo lớp thành công và nhận Class Code duy nhất.
* Học sinh nhập Class Code và xin tham gia (trạng thái Pending).
* Giáo viên duyệt/từ chối/xóa học sinh hoạt động đúng.
* Học sinh chỉ thấy nội dung lớp sau khi được duyệt.
* Giới hạn 50 học sinh/lớp được enforce.
* Class Code case-insensitive.
* Giáo viên chỉ quản lý được lớp mình tạo.
