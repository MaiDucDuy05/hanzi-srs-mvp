## 1. Yêu cầu nghiệp vụ

Giáo viên soạn bài kiểm tra từ ngân hàng câu hỏi (cả Public của hệ thống và Private của mình), cấu hình thời gian/điều kiện, rồi giao cho lớp hoặc một số học sinh cụ thể.

### 1.1. Luồng giáo viên tạo đề

1. Giáo viên vào trang "Bài kiểm tra" → bấm "Tạo bài mới".
2. Nhập thông tin cơ bản: Tên bài, Mô tả, Cấp HSK (optional).
3. Chọn câu hỏi từ ngân hàng:
   - Duyệt theo Filter: Cấp HSK, Loại câu hỏi, Tag, Nguồn (Public/Private).
   - Tick chọn câu hỏi muốn thêm → Thêm vào đề.
   - Hoặc: "Chọn ngẫu nhiên N câu" theo bộ lọc (random pick).
4. Sắp xếp thứ tự câu hỏi bằng kéo thả (drag & drop).
5. Cấu hình bài:
   - Thời gian làm bài (phút), 0 = không giới hạn.
   - Xáo trộn thứ tự câu hỏi cho mỗi học sinh (có/không).
   - Cho phép xem đáp án đúng sau khi nộp (có/không).
   - Số lần làm lại tối đa (1 = chỉ làm 1 lần).
6. Bấm "Lưu nháp" hoặc "Xuất bản và giao bài".

### 1.2. Luồng giao bài

1. Sau khi tạo xong đề, giáo viên chọn đối tượng nhận:
   - **Cả lớp**: Chọn một hoặc nhiều lớp.
   - **Học sinh cụ thể**: Tick từng học sinh trong lớp.
2. Cấu hình thời gian:
   - `start_time`: Ngày giờ mở bài (trước thời điểm này học sinh không thấy bài).
   - `end_time`: Hạn chót nộp bài.
3. Bấm "Giao bài" → Hệ thống tạo assignment và thông báo cho học sinh.

### 1.3. Luồng học sinh làm bài

1. Học sinh vào trang "Bài được giao" → thấy danh sách bài kiểm tra.
2. Bấm "Bắt đầu" → Hệ thống tạo `exam_attempt`, bắt đầu đếm ngược thời gian.
3. Trả lời từng câu, có thể quay lại câu trước.
4. Bấm "Nộp bài" hoặc tự động nộp khi hết thời gian.
5. Backend chấm điểm tự động (với câu hỏi trắc nghiệm, điền từ, sắp xếp).
6. Nếu cấu hình cho phép: hiển thị đáp án đúng và giải thích.

### 1.4. Quy tắc chính

* Giáo viên chỉ sửa/xóa được bài kiểm tra do mình tạo.
* Bài kiểm tra đã có học sinh nộp → không được xóa câu hỏi (chỉ được thêm hoặc ẩn).
* Backend chấm điểm, không tin cậy điểm do client gửi.
* Một bài kiểm tra có thể giao cho nhiều lớp.
* Học sinh chỉ thấy bài kiểm tra trong khoảng `start_time` đến `end_time`.
* Thời gian làm bài tính từ lúc bấm "Bắt đầu", không phải lúc mở trang.

## 2. Thiết kế dữ liệu

## 3. Triển khai Backend — NestJS

### 3.1. Cấu trúc module

```text
exam/
  exam.controller.ts           # CRUD đề + giao bài
  exam.service.ts
  exam-taking.controller.ts    # Học sinh làm bài
  exam-taking.service.ts
  exam-grading.service.ts      # Chấm điểm
  entities/
  dto/
```

### 3.2. API cần triển khai

**Giáo viên (Teacher):**

| Method | Endpoint | Chức năng |
| :--- | :--- | :--- |
| POST | `/api/exams` | Tạo bài kiểm tra mới |
| GET | `/api/exams` | Danh sách bài của mình |
| GET | `/api/exams/:id` | Chi tiết bài (kèm câu hỏi) |
| PUT | `/api/exams/:id` | Cập nhật bài kiểm tra |
| DELETE | `/api/exams/:id` | Xóa bài (chỉ nếu chưa có ai nộp) |
| POST | `/api/exams/:id/questions` | Thêm câu hỏi vào đề |
| PUT | `/api/exams/:id/questions/order` | Sắp xếp lại thứ tự |
| POST | `/api/exams/:id/assign` | Giao bài cho lớp/học sinh |
| GET | `/api/exams/:id/results` | Xem kết quả toàn bộ |

**Học sinh (Student):**

| Method | Endpoint | Chức năng |
| :--- | :--- | :--- |
| GET | `/api/exam-taking/assigned` | Danh sách bài được giao |
| POST | `/api/exam-taking/:examId/start` | Bắt đầu làm bài |
| POST | `/api/exam-taking/:attemptId/submit` | Nộp bài |
| GET | `/api/exam-taking/:attemptId/result` | Xem kết quả |

### 3.3. Luồng chấm điểm tự động

1. Học sinh nộp bài → Backend nhận `answers[]`.
2. Với mỗi câu, so sánh đáp án với `correct_answer` trong bảng `questions`.
3. Các loại câu hỏi:
   - **Trắc nghiệm**: So sánh trực tiếp option ID.
   - **Điền từ**: So sánh text (trim, lowercase, normalize).
   - **Sắp xếp câu**: So sánh mảng thứ tự.
4. Tính `score = (correct_count / total_questions) * 100`.
5. Lưu kết quả, cập nhật status = `GRADED`.

### 3.4. Xử lý lỗi

* Tạo bài không có câu hỏi: Cho phép lưu nháp nhưng không cho giao bài.
* Làm bài quá hạn `end_time`: Không cho bắt đầu, trả lỗi `EXAM_EXPIRED`.
* Hết thời gian làm bài: Backend tự động chấm với các câu đã trả lời.
* Vượt `max_attempts`: Trả lỗi `MAX_ATTEMPTS_REACHED`.
* Xóa bài đã có người nộp: Trả lỗi `EXAM_HAS_SUBMISSIONS`.

## 4. Triển khai Frontend — NextJS

### 4.1. Route và thành phần

| Route/Component | Vai trò |
| :--- | :--- |
| `/teacher/exams` | Danh sách bài kiểm tra của giáo viên |
| `/teacher/exams/create` | Tạo bài mới |
| `/teacher/exams/[id]/edit` | Chỉnh sửa bài |
| `/teacher/exams/[id]/assign` | Giao bài cho lớp |
| `/teacher/exams/[id]/results` | Xem kết quả toàn bộ |
| `/student/exams` | Danh sách bài được giao |
| `/student/exams/[attemptId]` | Màn hình làm bài |
| `QuestionPicker` | Component chọn câu hỏi từ ngân hàng |
| `ExamTimer` | Đếm ngược thời gian |

### 4.2. Cách xử lý giao diện

* **Tạo đề:** Giao diện 2 panel — bên trái là ngân hàng câu hỏi (có filter), bên phải là đề đang soạn (drag & drop sắp xếp).
* **Làm bài:** Sidebar liệt kê số câu (click để nhảy). Trạng thái câu: Chưa làm / Đã làm / Đã đánh dấu.
* **Timer:** Cố định ở header, đổi màu đỏ khi còn 5 phút. Khi hết giờ, tự động submit.
* Lưu đáp án tạm vào `localStorage` mỗi 10 giây để tránh mất khi refresh.

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo bảng `exams`, `exam_questions`, `exam_assignments`, `exam_attempts`.
2. API CRUD bài kiểm tra (Teacher).
3. API giao bài (assign).
4. API bắt đầu/nộp bài (Student).
5. Service chấm điểm tự động.
6. Frontend Teacher: Trang tạo đề + QuestionPicker.
7. Frontend Student: Trang làm bài + Timer.
8. Frontend Teacher: Trang xem kết quả.

## 6. Tiêu chí hoàn thành

PR-05 được nghiệm thu khi:

* Giáo viên tạo được bài kiểm tra từ ngân hàng câu hỏi.
* Có thể kéo thả sắp xếp thứ tự câu hỏi.
* Giao bài cho lớp hoặc cá nhân thành công với cấu hình thời gian.
* Học sinh chỉ thấy bài trong khoảng start_time đến end_time.
* Countdown timer hoạt động, tự động nộp khi hết giờ.
* Backend chấm điểm chính xác cho các loại câu hỏi (trắc nghiệm, điền từ, sắp xếp).
* Không thể nộp bài quá số lần quy định hoặc quá hạn chót.
* Giáo viên xem được kết quả toàn bộ học sinh.
