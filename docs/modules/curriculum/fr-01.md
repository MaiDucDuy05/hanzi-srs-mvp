# ĐẶC TẢ FR-01
## Danh mục từ vựng/ngữ pháp theo cấp
*Bản triển khai MVP cho đội dự án nhỏ*

---

| Thông tin | Nội dung |
| :--- | :--- |
| Mã chức năng | FR-01 |
| Actor | Free, VIP, Teacher, Admin |
| Backend | NestJS + PostgreSQL |
| Frontend | NextJS |
| Lưu trữ audio | AWS S3 + CloudFront |
| Ưu tiên | Cao |

## 1. Yêu cầu nghiệp vụ

Hệ thống tổ chức nội dung theo cấu trúc:

**Cấp HSK** -> **Bài học** -> **Từ vựng và ngữ pháp**

Người học cần thực hiện được các thao tác sau:
* Chọn một cấp từ HSK1 đến HSK9.
* Xem danh sách bài học thuộc cấp đã chọn.
* Mở bài và xem từ vựng, ngữ pháp theo đúng thứ tự.
* Với mỗi từ vựng, xem được chữ Hán, pinyin, nghĩa tiếng Việt và nghe audio.

Admin cần thực hiện được các thao tác sau:
* Tạo, sửa và xoá mềm bài học.
* Tạo, sửa từ vựng và ngữ pháp trong bài.
* Upload audio cho từ vựng.
* Lưu bản nháp hoặc xuất bản bài học.
* Sắp xếp thứ tự bài học và nội dung trong bài.

> **Giới hạn MVP:** Chỉ xây đủ chức năng nhập và đọc nội dung. Chưa cần lịch sử phiên bản, quy trình duyệt nhiều bước, audit log chi tiết hoặc tìm kiếm nâng cao.

### 1.1. Quy tắc chính

* Mỗi bài học thuộc đúng một cấp HSK.
* Học viên chỉ xem được bài có trạng thái `PUBLISHED`.
* Admin có thể lưu bài ở trạng thái `DRAFT` khi nội dung chưa hoàn thiện.
* Từ vựng phải có chữ Hán, pinyin, nghĩa tiếng Việt và audio trước khi xuất bản.
* Xoá bài bằng xoá mềm để không ảnh hưởng dữ liệu bài tập sử dụng sau này.
* Chỉ Admin được phép thêm, sửa, xoá và xuất bản nội dung.

## 2. Thiết kế dữ liệu tối thiểu

Chỉ cần năm bảng chính cho phiên bản đầu:

| Bảng | Dữ liệu cần lưu |
| :--- | :--- |
| `hsk_levels` | Mã HSK1--9, tên và thứ tự. |
| `lessons` | Cấp HSK, tiêu đề, mô tả, thứ tự, trạng thái và thời gian xoá mềm. |
| `vocabularies` | Chữ Hán, pinyin, nghĩa Việt, S3 audio key và cấp HSK. |
| `grammar_points` | Tiêu đề, cấu trúc, giải thích và cấp HSK. |
| `lesson_contents` | Liên kết bài với từ vựng/ngữ pháp, loại nội dung và thứ tự hiển thị. |

**Gợi ý đơn giản hoá:** dùng một bảng `lesson_contents` thay cho hai bảng liên kết riêng. Trường `contentType` nhận giá trị `VOCABULARY` hoặc `GRAMMAR`; trường `contentId` lưu ID nội dung tương ứng.

Các bảng dùng UUID cùng hai trường thời gian `createdAt` và `updatedAt`. Bảng `lessons` có thêm trạng thái, thứ tự hiển thị và thời gian xoá mềm.

## 3. Triển khai Backend -- NestJS

### 3.1. Cấu trúc module

Không cần chia quá nhiều lớp trong giai đoạn đầu:

```text
curriculum/
  curriculum.controller.ts
  admin-curriculum.controller.ts
  curriculum.service.ts
  curriculum.repository.ts
  dto/
  entities/
```

* **Controller người học:** API đọc cấp HSK, bài học và chi tiết bài.
* **Controller Admin:** API tạo, sửa, xoá, upload và xuất bản.
* **Service:** kiểm tra quy tắc nghiệp vụ và điều phối transaction.
* **Repository:** truy vấn PostgreSQL bằng ORM đang dùng trong dự án.
* **DTO:** validate dữ liệu đầu vào bằng `class-validator`.

### 3.2. API cần triển khai

| Method | Endpoint | Chức năng |
| :--- | :--- | :--- |
| GET | `/api/hsk-levels` | Danh sách HSK1--9. |
| GET | `/api/hsk-levels/:code/lessons` | Danh sách bài đã xuất bản. |
| GET | `/api/lessons/:id` | Chi tiết bài, từ vựng và ngữ pháp. |
| POST | `/api/admin/lessons` | Tạo bài nháp. |
| PATCH | `/api/admin/lessons/:id` | Sửa bài và nội dung. |
| DELETE | `/api/admin/lessons/:id` | Xoá mềm bài. |
| POST | `/api/admin/lessons/:id/publish` | Xuất bản bài. |
| POST | `/api/admin/audio/presign` | Lấy URL upload audio lên S3. |

### 3.3. Luồng lưu bài

1. Frontend gửi thông tin bài và danh sách nội dung.
2. Backend xác thực Admin và validate DTO.
3. Service lưu bài cùng `lesson_contents` trong một transaction.
4. Nếu chọn xuất bản, backend kiểm tra các trường bắt buộc.
5. Backend trả về bài đã lưu để frontend cập nhật giao diện.

### 3.4. Upload audio

1. Frontend yêu cầu presigned URL từ backend.
2. Backend kiểm tra quyền Admin và trả URL upload có thời hạn.
3. Frontend upload file trực tiếp lên S3.
4. Sau khi upload thành công, frontend lưu S3 object key vào từ vựng.
5. Khi người học mở bài, backend hoặc CloudFront trả URL phát audio.

Chỉ cần hỗ trợ MP3, giới hạn dung lượng file và kiểm tra MIME type. Không cần xây media service riêng ở phiên bản đầu.

### 3.5. Phân quyền và hiệu năng

* Dùng JWT/Cognito Guard hiện có; thêm Role Guard cho Admin.
* Mọi API ghi dữ liệu phải kiểm tra quyền ở backend.
* Tạo index cho `lessons(levelId, status, displayOrder)`.
* Chưa cần Redis ngay. Chỉ bổ sung cache khi dữ liệu hoặc lưu lượng tăng.
* API danh sách chỉ trả dữ liệu tóm tắt; chi tiết nội dung tải khi mở bài.

## 4. Triển khai Frontend -- NextJS

### 4.1. Màn hình người học

Chỉ cần ba trang:

| Route | Nội dung |
| :--- | :--- |
| `/learn` | Card HSK1--9. |
| `/learn/[levelCode]` | Danh sách bài thuộc cấp đã chọn. |
| `/learn/[levelCode]/[lessonId]` | Chi tiết bài, tab từ vựng/ngữ pháp và nút phát audio. |

Trang danh sách và chi tiết dùng Server Component để lấy dữ liệu ban đầu. Nút audio và tab nội dung dùng Client Component.

Mỗi trang cần có loading, thông báo lỗi và empty state. Giao diện responsive web; không xây ứng dụng mobile.

### 4.2. Màn hình Admin

Xây một trang danh sách và một trang chỉnh sửa:

* `/admin/curriculum`: lọc theo cấp, xem danh sách bài, tạo bài mới.
* `/admin/curriculum/lessons/[id]`: nhập tiêu đề, nội dung, audio, thứ tự và trạng thái.

Form chỉnh sửa nên có các nút **Lưu nháp**, **Xuất bản** và **Xoá**. Giai đoạn đầu có thể dùng nút lên/xuống để đổi thứ tự thay vì kéo thả, giúp giảm thời gian phát triển.

Upload audio cần hiển thị tiến trình và nút nghe thử. Nếu upload lỗi, giữ nguyên dữ liệu form để Admin thử lại.

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo migration và seed sẵn HSK1--9.
2. Làm API đọc danh sách cấp, bài và chi tiết bài.
3. Làm ba trang học viên để kiểm tra dữ liệu end-to-end.
4. Làm API Admin tạo/sửa bài và nội dung.
5. Làm form Admin và chức năng lưu nháp/xuất bản.
6. Tích hợp upload audio S3.
7. Bổ sung xoá mềm, phân quyền và xử lý lỗi.
8. Nhập một số bài mẫu, test hoàn chỉnh rồi mới nhập dữ liệu số lượng lớn.

> **Khuyến nghị:** Một người làm backend/schema/API trước; người làm frontend có thể dùng dữ liệu mock theo response đã thống nhất. Khi API đọc hoàn thành, kết nối frontend trước rồi mới phát triển trang Admin.

## 6. Tiêu chí hoàn thành

FR-01 được nghiệm thu khi:

* Người dùng chọn được HSK1--9 và xem đúng bài đã xuất bản.
* Bài học hiển thị đúng từ vựng, ngữ pháp và thứ tự.
* Mỗi từ vựng có chữ Hán, pinyin, nghĩa Việt và audio phát được.
* Admin tạo, sửa, lưu nháp, xuất bản và xoá mềm được bài học.
* Người không phải Admin không gọi được API quản trị.
* Dữ liệu bài và nội dung được lưu an toàn trong cùng transaction.
* Giao diện hoạt động tốt trên desktop và mobile web responsive.
