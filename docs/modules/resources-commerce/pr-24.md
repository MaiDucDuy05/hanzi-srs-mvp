## 1. Yêu cầu nghiệp vụ

Kho tài liệu tham khảo (slide, đề thi, tài liệu tổng hợp). Phân loại theo gói Free/VIP.

### 1.1. Luồng upload (Teacher/Admin)

1. Vào trang "Thư viện tài liệu" → bấm "Upload tài liệu".
2. Chọn file (drag & drop hoặc browse).
3. Nhập metadata:
   - Tiêu đề.
   - Mô tả (optional).
   - Danh mục: Đề thi, Slide bài giảng, Tài liệu tổng hợp, Khác.
   - Cấp HSK liên kết (optional).
   - Quyền truy cập: `FREE` (ai cũng tải) hoặc `VIP` (chỉ VIP+).
4. Bấm "Upload" → File upload lên S3, metadata lưu DB.

### 1.2. Luồng xem/tải (Học viên)

1. Vào trang "Thư viện tài liệu".
2. Duyệt theo danh mục, HSK level, hoặc search.
3. Tài liệu `FREE`: Click "Tải xuống" → nhận presigned URL → tải file.
4. Tài liệu `VIP`:
   - Free User: Nút "Tải xuống" bị khóa, hiện tooltip "Nâng cấp VIP để tải".
   - VIP User: Click "Tải xuống" → nhận presigned URL (có hạn 15 phút).

### 1.3. Quy tắc chính

* Định dạng cho phép: `.pdf`, `.ppt`, `.pptx`, `.doc`, `.docx`.
* Dung lượng tối đa: 50 MB/file.
* Presigned URL download có hạn 15 phút, không thể chia sẻ lại.
* Teacher chỉ xóa được tài liệu mình upload. Admin xóa được tất cả.
* Tài liệu xóa mềm (soft delete), file trên S3 giữ lại 30 ngày.

## 3. Triển khai Backend — NestJS

### 3.1. API cần triển khai

| Method | Endpoint | Actor | Chức năng |
| :--- | :--- | :--- | :--- |
| POST | `/api/resources/upload-url` | Teacher, Admin | Lấy presigned PUT URL để upload |
| POST | `/api/resources` | Teacher, Admin | Xác nhận upload xong, lưu metadata |
| GET | `/api/resources` | All | Danh sách tài liệu (filter, pagination) |
| GET | `/api/resources/:id` | All | Chi tiết tài liệu |
| GET | `/api/resources/:id/download` | All (VIP check) | Lấy presigned GET URL để tải |
| PUT | `/api/resources/:id` | Owner, Admin | Cập nhật metadata |
| DELETE | `/api/resources/:id` | Owner, Admin | Soft delete |

### 3.2. Luồng upload

1. Client gọi `POST /upload-url` với `fileName`, `fileType`, `fileSize`.
2. Backend validate (định dạng, dung lượng) → sinh presigned PUT URL cho S3.
3. Client upload trực tiếp lên S3.
4. Client gọi `POST /resources` với metadata + S3 key → Backend xác nhận file tồn tại (HEAD) → lưu DB.

### 3.3. Luồng download

1. Client gọi `GET /resources/:id/download`.
2. Backend kiểm tra:
   - Tài liệu `FREE` → Sinh presigned GET URL, trả về.
   - Tài liệu `VIP` → Kiểm tra user role. Nếu Free User → 403 `VIP_REQUIRED`. Nếu VIP+ → Sinh URL.
3. Tăng `download_count`.
4. Presigned URL hết hạn sau 15 phút.

### 3.4. Xử lý lỗi

* File sai định dạng: `INVALID_FILE_TYPE`.
* File quá lớn: `FILE_TOO_LARGE`.
* Free User tải VIP: `VIP_REQUIRED` + thông tin gói VIP.
* Presigned URL hết hạn: Client gọi lại API `/download`.

## 4. Triển khai Frontend — NextJS

| Route/Component | Vai trò |
| :--- | :--- |
| `/resources` | Trang thư viện tài liệu |
| `/resources/upload` | Trang upload (Teacher/Admin) |
| `ResourceCard` | Card tài liệu (icon file type, title, badge FREE/VIP) |
| `UploadDropzone` | Khu vực kéo thả file |
| `DownloadButton` | Nút tải (khóa nếu VIP required) |
| `VipUpgradeModal` | Popup gợi ý nâng cấp khi Free click VIP resource |

### 4.1. Cách xử lý giao diện

* Trang thư viện: Grid card tài liệu + sidebar filter (danh mục, HSK, access level).
* Badge VIP: Tag vàng "VIP" trên card. Badge FREE: Tag xanh.
* Upload: Drag & drop zone + progress bar + validation real-time (kiểm tra file type/size trước khi upload).
* Trên mobile: Grid 1 cột, filter collapse.

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo bảng `resources`.
2. API upload (presigned URL + metadata).
3. API danh sách + filter + pagination.
4. API download với VIP check.
5. Frontend: Upload page + dropzone.
6. Frontend: Library page + cards + filter.
7. VipUpgradeModal cho Free User.

## 6. Tiêu chí hoàn thành

PR-24 được nghiệm thu khi:

* Teacher/Admin upload được tài liệu lên S3.
* Thư viện hiển thị đúng với filter theo danh mục, HSK, access level.
* Free User tải được tài liệu FREE.
* Free User bị chặn khi tải VIP, hiện popup nâng cấp.
* VIP User tải được tài liệu VIP qua presigned URL.
* Presigned URL hết hạn sau 15 phút.
* Validation file type và size hoạt động cả frontend và backend.
