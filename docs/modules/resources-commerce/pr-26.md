## 1. Yêu cầu nghiệp vụ

Học viên gửi yêu cầu nâng cấp VIP, thanh toán bằng chuyển khoản ngân hàng. Admin xác nhận thủ công và kích hoạt gói.

### 1.1. Luồng người dùng đăng ký VIP

1. Free User bấm "Nâng cấp VIP" (từ popup giới hạn lượt, trang pricing, hoặc menu).
2. Trang Pricing hiển thị các gói:
   - **1 tháng**: XXX.000 VNĐ.
   - **6 tháng**: XXX.000 VNĐ (giảm X%).
   - **1 năm**: XXX.000 VNĐ (giảm X%).
3. User chọn gói → Hiển thị thông tin chuyển khoản:
   - Mã QR VietQR (sinh động bằng VietQR API hoặc ảnh tĩnh).
   - Tên ngân hàng + Số tài khoản + Chủ tài khoản.
   - Nội dung chuyển khoản: `HSK {userId_short}` (6 ký tự cuối UUID).
   - Số tiền chính xác.
4. User chuyển khoản xong → bấm "Tôi đã thanh toán".
5. Trạng thái chuyển thành `PENDING_PAYMENT`.
6. Hiển thị: "Yêu cầu của bạn đang được xử lý. Vui lòng chờ xác nhận trong vòng 24h."

### 1.2. Luồng Admin duyệt

1. Admin vào Dashboard → tab "Yêu cầu VIP".
2. Danh sách: User, Gói, Số tiền, Ngày gửi, Trạng thái.
3. Admin kiểm tra biến động số dư ngân hàng (thủ công bên ngoài hệ thống).
4. Nếu đã nhận tiền:
   - Bấm "Kích hoạt" → Trạng thái: `ACTIVE`.
   - Hệ thống tính `vip_valid_until = now() + duration`.
   - Cập nhật role user từ `FREE` → `VIP`.
   - Gửi email thông báo cho user (qua Brevo).
5. Nếu không nhận tiền hoặc nghi ngờ:
   - Bấm "Từ chối" + nhập lý do.
   - Gửi email thông báo cho user.

### 1.3. Hết hạn VIP

1. Cron job chạy hàng ngày lúc 00:00.
2. Kiểm tra user nào có `vip_valid_until < now()`.
3. Chuyển role về `FREE`.
4. Gửi email nhắc gia hạn 3 ngày trước khi hết hạn.
5. Gửi email thông báo hết hạn khi chuyển về FREE.

### 1.4. Quy tắc chính

* Giá gói VIP cấu hình qua bảng `system_config` (Admin thay đổi không cần deploy).
* Một user chỉ có tối đa 1 yêu cầu PENDING tại một thời điểm.
* Nếu user đã là VIP và mua thêm: Cộng dồn thời hạn (extend, không reset).
* Nội dung CK phải chứa mã định danh user để Admin đối soát.

### 3.3. Logic kích hoạt

```typescript
async approveSubscription(subscriptionId, adminId) {
  const sub = await this.findById(subscriptionId);
  const user = await this.userService.findById(sub.userId);
  
  // Tính thời hạn
  const duration = this.getDuration(sub.plan); // 30, 180, 365 ngày
  const validFrom = new Date();
  let validUntil: Date;
  
  // Nếu user đang VIP → cộng dồn
  if (user.vipValidUntil && user.vipValidUntil > validFrom) {
    validUntil = addDays(user.vipValidUntil, duration);
  } else {
    validUntil = addDays(validFrom, duration);
  }
  
  // Cập nhật subscription
  sub.status = 'ACTIVE';
  sub.approvedBy = adminId;
  sub.approvedAt = validFrom;
  sub.validFrom = validFrom;
  sub.validUntil = validUntil;
  
  // Cập nhật user
  user.role = 'VIP';
  user.vipValidUntil = validUntil;
  
  // Lưu + gửi email
  await this.save(sub);
  await this.userService.save(user);
  await this.emailService.sendVipActivated(user, sub);
}
```

### 4.1. Cách xử lý giao diện

* Trang Pricing: 3 card gói (1 tháng, 6 tháng, 1 năm). Card phổ biến nhất có viền highlight.
* QR thanh toán: Render bằng VietQR API (`https://img.vietqr.io/image/{bank}-{account}-...`). Hiển thị kèm nội dung CK rõ ràng.
* Trạng thái yêu cầu: Stepper (Đã gửi → Đang xử lý → Hoàn thành).
* Admin: Bảng danh sách + nút Approve/Reject + modal nhập lý do từ chối.

## 6. Tiêu chí hoàn thành

PR-26 được nghiệm thu khi:

* User chọn gói, xem QR chuyển khoản với nội dung CK chứa mã user.
* Bấm "Đã thanh toán" → trạng thái PENDING_PAYMENT.
* Admin approve → role chuyển thành VIP, email gửi cho user.
* Admin reject → email gửi lý do cho user.
* Cộng dồn thời hạn nếu user đã là VIP.
* Cron job tự chuyển về FREE khi hết hạn.
* Email nhắc gia hạn 3 ngày trước khi hết hạn.
* Chỉ cho phép 1 yêu cầu PENDING tại một thời điểm.
