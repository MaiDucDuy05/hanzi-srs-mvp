## 1. Yêu cầu nghiệp vụ

Ghi lại các câu hỏi học viên làm sai, cho phép ôn tập lại và tự động xóa khi đã nắm vững.

### 1.1. Luồng thêm vào sổ

1. Học viên làm bài tập/kiểm tra và trả lời sai một câu.
2. Backend tự động thêm câu hỏi đó vào sổ lỗi sai của user (nếu chưa có).
3. Nếu câu đã có trong sổ: Cập nhật `last_failed_at` và tăng `fail_count`.

### 1.2. Luồng ôn tập sổ lỗi sai

1. Học viên vào trang "Sổ lỗi sai".
2. Xem danh sách câu hỏi sai (filter theo HSK, loại, ngày).
3. Bấm "Ôn tập" → Hệ thống tạo mini-quiz random từ các câu trong sổ.
4. Trả lời đúng → `correct_streak` + 1. Trả lời sai → `correct_streak` reset về 0.
5. Khi `correct_streak` đạt 2 (đúng 2 lần liên tiếp) → Tự động xóa câu khỏi sổ.

### 1.3. Quy tắc chính

* Sổ lỗi sai là cá nhân, mỗi user có sổ riêng.
* Giáo viên có thể xem sổ lỗi sai của học sinh trong lớp mình (read-only).
* Tối đa 500 câu hỏi/sổ. Khi đầy, câu cũ nhất (theo `last_failed_at`) bị thay thế.
* Ôn tập sổ lỗi sai không bị giới hạn lượt (kể cả Free User).

### 3.3. Logic thêm vào sổ (Internal Service)

```typescript
// Được gọi từ PracticeService và ExamGradingService
async addToMistakeBook(userId, questionOrVocabId, sourceType, sourceId, userAnswer, correctAnswer) {
  const existing = await this.findByUserAndQuestion(userId, questionOrVocabId);
  if (existing) {
    existing.failCount++;
    existing.lastFailedAt = new Date();
    existing.correctStreak = 0; // Reset streak
    return this.save(existing);
  }
  // Kiểm tra giới hạn 500
  const count = await this.countByUser(userId);
  if (count >= 500) {
    await this.removeOldest(userId);
  }
  return this.create({ userId, questionOrVocabId, sourceType, sourceId, userAnswer, correctAnswer });
}
```

### 3.4. Logic ôn tập

1. `POST /review/start`: Random tối đa 10 câu từ sổ, ưu tiên câu có `fail_count` cao và `last_reviewed_at` cũ.
2. `POST /review/:id/submit`: Chấm từng câu:
   - Đúng: `correct_streak++`. Nếu `correct_streak >= 2` → Xóa khỏi sổ.
   - Sai: `correct_streak = 0`, `fail_count++`, `last_failed_at = now()`.

| Route/Component | Vai trò |

### 4.2. Cách xử lý giao diện

* Danh sách sổ lỗi hiển thị dạng card hoặc list, có badge số lần sai.
* `StreakIndicator` cho thấy tiến trình "sắp xóa" (2 dots: filled = đúng, empty = chưa).
* Khi câu hỏi bị xóa khỏi sổ sau ôn tập: Animation confetti nhỏ + toast "Đã nắm vững!".
* Nút "Ôn tập" hiển thị badge số câu trong sổ.

## 5. Thứ tự triển khai cho đội nhỏ

1. Tạo bảng `mistake_books`.
2. Service `addToMistakeBook` — tích hợp vào các practice/exam service hiện có.
3. API danh sách + filter.
4. API ôn tập (start + submit) với logic streak.
5. Frontend: Trang sổ lỗi sai + filter.
6. Frontend: Màn hình ôn tập.
7. Tích hợp xem sổ lỗi sai học sinh cho giáo viên (PR-23).

## 6. Tiêu chí hoàn thành

PR-17 được nghiệm thu khi:

* Câu hỏi sai tự động thêm vào sổ khi làm bài tập/kiểm tra.
* Danh sách sổ lỗi sai hiển thị đúng với filter.
* Ôn tập hoạt động: Đúng 2 lần liên tiếp → xóa khỏi sổ.
* Sai khi ôn tập → reset streak về 0.
* Giới hạn 500 câu/sổ, tự thay thế câu cũ nhất.
* Giáo viên xem được sổ lỗi sai của học sinh trong lớp.
* Ôn tập sổ lỗi không bị giới hạn lượt (kể cả Free).
